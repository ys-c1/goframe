# 同一 tick 内重复指令：去重的充要条件、丢量公式与审计留档

## 0. 问题

同一 tick 收到两条完全相同的指令 `c`（同一 `Body`、同一 `PushX/PushY`、同一 `Tick`）：

```
cmds = [c, c]
```

「执行两次」与「去重一次」结果不同。本文回答三件事：

1. 去重无损的**充要条件**是什么；
2. 不满足条件时**丢多少冲量**，丢量与指令数的关系；
3. 三组输入的去重前后哈希、丢失冲量与判定，以及去重判定本身的**开销**。

实现：`api/dedup.go`；审计与留档：`api/audit.go`；测试：`api/*_test.go`。

---

## 1. 模型

### 1.1 指令对状态的贡献

`World.Step`（`api/api.go:65`）对每条指令只做一件事：

```go
w.state.Push(c.Body, fixed.FromRaw(c.PushX), fixed.FromRaw(c.PushY))
```

`Push` 是两次定点加法（`internal/sim/sim.go:28`）：

```
velX[b] += dx        velY[b] += dy
```

随后 `Integrate` 只读状态、不再看指令。于是：

> **一帧内所有指令对状态的作用，只经由「对 (b, velX) 与 (b, velY) 的加法」发生，
> 且加法在 Q16.16 的 int32 表示下按模 2³² 回绕。**

`fixed.Value` 是 `int32`；Go 的 int32 加法与 `int32(int64(a)*int64(b))` 都按模 2³² 回绕。
这正是下面所有结论的代数基础：**贡献向量在加法群 (ℤ/2³², +) 内，且与执行顺序无关**（加法可交换）。

### 1.2 每个指令的「写入集」

把指令 `c` 看成对状态坐标的写操作：

```
W(c) = { (c.Body, velX)  if c.PushX ≠ 0
         (c.Body, velY)  if c.PushY ≠ 0 }
```

零分量不写（加 0 是恒等）。目标坐标对是 `(Body, 字段)`；这就是题目里
「目标与字段的交集」的精确含义：

```
Touch(a, b) = { 坐标 }  a 与 b 都写
```

`Independent(a,b) ⟺ Touch(a,b) = ∅`（`api/dedup.go` 的 `Independent`）。

## 2. 去重无损的充要条件

### 2.0 先固定「贡献」的代数

把一条指令 `c` 的贡献记成状态坐标上的增量向量

```
δ(c) ∈ (ℤ/2³²)^(2B)        δ(c)[(Body, velX)] = PushX
                            δ(c)[(Body, velY)] = PushY
```

`Push` 只做加法（`internal/sim/sim.go:28`），`Integrate` 是状态的确定性函数，故：

> **一帧内全部指令对状态的贡献 = Σ_c δ(c)**（按坐标逐项、模 2³² 相加），
> 与执行顺序无关（加法在 (ℤ/2³²,+) 中可交换、可结合）。

这就是题目里「贡献可加」的准确形式：**在这个内核里，加法恒成立**，不需要额外条件。
「互不依赖」的作用不在于可加性，而在于**去重是否等价于少执行**——见下。

### 2.1 「执行 m 次」与「只留一条」

m 条完全相同的指令 `c`（同一 Tick、Body、PushX/PushY）：

```
执行 m 次： 贡献 = m·δ(c)
去重留一条： 贡献 = δ(c)          （丢弃副本）
归并折次数： 贡献 = m·δ(c)        （把 m 折进冲量，见 §2.3）
```

于是**丢弃副本无损 ⟺ `m·δ(c) ≡ δ(c)` ⟺ `(m-1)·δ(c) ≡ 0 (mod 2³²)`**。

- **m = 2（本题的情形）**：`m−1 = 1` 在环 ℤ/2³² 中可逆，故 `iff δ(c) ≡ 0`，干净利落。
- **m ≥ 3**：`m−1` 可能非可逆（偶数）；此时 `(m−1)δ ≡ 0` 还有非零解，
  例如 `m = 3, δ = 2³¹`：`(3−1)·2³¹ = 2³² ≡ 0`，丢弃两次反而无损（实测见 `api/loss_test.go`）。
  这正是模运算的边界，§2.4 末尾单列。

### 2.2 写入集与「目标、字段的交集」

```
W(c) = { (c.Body, velX) if c.PushX ≠ 0 ; (c.Body, velY) if c.PushY ≠ 0 }
Touch(a, b) = W(a) ∩ W(b)
```

`Independent(a,b) ⟺ Touch(a,b) = ∅`（`api/dedup.go` 的 `Independent`）。
零分量不写状态（加 0 是恒等），故零分量不进写入集。

对**两条完全相同**的指令，`Touch(c,c) = W(c)`，于是

```
交集为空  ⟺  W(c) = ∅  ⟺  δ(c) ≡ 0
```

### 2.3 定理 A（问题原型：同一 tick 两条相同指令）

> 「去重只留一条」与「执行两次」逐项相同
> **⟺ 两条指令目标与字段的交集为空 ⟺ 冲量向量 δ(c) ≡ 0 (mod 2³²)**。

证明：
- **充分**：交集为空 ⇒ `δ(c) = 0` ⇒ 两次执行与一次执行贡献都是 0，状态逐帧相同。
- **必要**：交集非空 ⇒ 存在被两条指令都写的坐标且该分量 `d ≠ 0`。
  两次执行在该坐标累加 `2d`，去重只累加 `d`，差为 `d ≠ 0 (mod 2³²)`；
  `Integrate` 无条件执行 `pos += vel`，速度差会原样（按 `SubSteps` 倍）进入位置，
  状态切片至少一项不同，哈希按所有项混合 ⇒ 指纹不同。

这正是题目所说的条件在「两条相同指令」上的形态：两份完全相同的非零指令**不互不依赖**
（交集就是自己的写入集），因此不能只留一条。

### 2.4 定理 B（一批指令：交集为空是丢弃副本的充分条件，但非必要）

> 若一批指令两两 `Independent`（目标与字段交集为空），则**每条指令写的是不同坐标**，
> 每个坐标只被写一次；丢弃任何副本都不会改变任何坐标的累加量，故**丢弃无损**。
> 反之，若某坐标被写了多次，丢弃副本会少算 `Σ (m_g−1)d_g`（按该坐标求和）。

但批级存在**对消**：某坐标上组 1 丢 `+2d`、组 2 丢 `−2d`，总和为 0，状态差为零，
**尽管两组交集都非空**。所以：

> **批级「丢弃无损」的精确充要条件是：每个 (实体, 分量) 的总丢量 `L_b ≡ 0`（§3.2）。**
> 「交集为空」只是充分条件，不是必要条件。

两个必须说清的边界：

1. **对两条相同指令（本题）**，交集为空 ⟺ 该组冲量为零，定理 A 的 iff 成立；
   「交集为空」既是充分也是必要。题目所说的充要条件在此**完全正确**。
   **但对 m ≥ 3 的重复组并不完全成立**：若 `m−1` 为偶数，`δ = 2³¹` 这类非零冲量的
   `(m−1)δ` 也会 ≡ 0，交集非空却丢弃无损（m=3、d=−2³¹ 已实测）。
2. **对多个组**，交集为空 ⇒ 无损，但反向不成立（可对消）。「交集为空」是充分的，
   真正的充要条件是逐坐标丢量和为零。随机对拍已覆盖这两种情形（`api/loss_test.go`，
其中 `TestDropLossEquivalence` 验证「状态相等 ⟺ 逐分量总丢量为零」；
`TestDropLossModularException` 钉住 m=3、d=2³¹ 这个反常点）。

### 2.5 为什么正确做法是「归并」而不是「丢弃」

把出现次数折进冲量：`m` 次 `d` 换成一次 `m·d`（`foldImpulse`，按 int32 回绕）。
在模 2³² 下 `m·d ≡ d + … + d`（m 次），**逐位恒等**，与 m 无关、与是否有交集无关。于是：

> **归并（折叠次数）恒无损；只有「丢弃副本」才依赖条件。**
> 工程上因此应当用归并，而不是「只留一条」。

## 3. 不满足条件时的丢量

### 3.1 单组：丢量与条数成正比

m 条相同指令、冲量 `d`，只留一条丢弃其余：

```
丢失 = (m - 1) · d          （模 2³²，按 int32 表示）
```

状态上表现为（`Δ = 原序 − 丢弃`）：

```
Δvel = (m-1)·d           （从第一个子步起一直保持）
Δpos = SubSteps · (m-1)·d
```

`Δpos` 的系数是 `SubSteps`：`Integrate` 每个子步都执行 `pos += vel`，速度差在每个子步都存在。

### 3.2 多组：按坐标求和，可对消

设本帧 k 条指令按 (Tick, Body, d) 分为 g 组，第 g 组 m_g 条、每条冲量 d_g，`Σ_g m_g = k`。
丢弃全部副本的总丢量**按 (Body, 分量) 分别求和**：

```
L_b = Σ_{g : Body=b} (m_g - 1) · d_g      （X/Y 分量各自求，模 2³²）
Δvel_b = L_b,    Δpos_b = SubSteps · L_b
```

要点：

- 丢量只取决于**每组的条数与冲量**，与 k 如何拆成组无关；若全不重复（g = k），`L = 0`，自动无损。
- **不同组的丢量可以对消**：`+2d` 与 `−2d` 相加为 0，状态差为零，尽管「某组非零」。
  所以「交集为空」（§2.2）只是充分条件，批级的**充要条件**是 `∀b : L_b ≡ 0`。
  已用随机对拍验证（`api/loss_test.go`，2000 组输入：丢弃后状态相等 ⟺ 每个 (实体, 分量) 的总丢量为零）。
- `d = 0`（零冲量副本）时 `L = 0`，丢弃无损，但仍被计为「重复」（`DropLoss` 会列出 `Count>1` 的组）。

丢量记录结构见 `api/dedup.go` 的 `ImpulseLoss`（`DX/DY` 为单条冲量，`Count` 为组内条数，
`LostX/LostY = foldImpulse(d, Count-1)`，与状态差分逐位一致）。

### 3.3 丢量与指令数的关系（一句话）

m 条相同指令的丢量是 `(m-1)·d`，**线性于超出 1 的条数**；k 条指令、g 个重复组的总丢量是
`Σ_g (m_g−1)·d_g`，**与顺序无关、只与各组的 `(m_g, d_g)` 有关**，且不同组间可对消。
就状态而言，丢量等价于「把每组多出的 `m_g−1` 份冲量从该实体对应分量里扣掉」。

## 5. 去重判定的开销

### 5.1 结论一句话

判定「有无重复」是 O(k²) 次四字段比较（有重复则提前返回）；有重复时再做一次 O(k)
复制与 O(k·g) 原地归并（g 为不同组数）。默认 8 实体 4 子步的整帧推进约 175–200 ns，
判定在 k ≤ 8 时约 25 ns（约整帧的 0.1x），k = 32 时约 0.3–0.35 µs（约 2x）。
**k 在常见量级（≤ 16）时判定远便宜于执行；一帧指令数上百时，判定开始比整帧还贵**
——此时应按 body 分桶或用位图，别让判定的常数超过执行本身。

### 5.2 实测（`TestDedupCostEstimate`，本机 i7-13620H，Go 1.26）

```
k=1   无重复≈1ns    全重复≈2ns     整帧≈200ns   倍数 ≈0.01x / ≈0.01x
k=8   无重复≈25ns   全重复≈150ns   整帧≈200ns   倍数 ≈0.1x  / ≈0.5x
k=32  无重复≈350ns  全重复≈250ns   整帧≈170ns   倍数 ≈2x    / ≈1.5x
k=128 无重复≈1.3µs  全重复≈1.1µs   整帧≈240ns   倍数 ≈5x    / ≈4x
```

（数字随机器与运行浮动，量级稳定。k=8 时「全重复」更慢：判定很快命中，但随后仍要复制并
归并、分配输出；k≥32 时「无重复」要跑满 k²/2 次比较，于是更慢。）

### 5.3 实现要点

- `DedupCommands` 先跑 `HasDuplicates`（两两比较，最坏 O(k²)，但每次比较只比四个 int32）；
  **无重复时直接原样返回入参，零分配**——这是常态帧的最优路径。
- 有重复时复制一份再 `dedupInPlaceLinear` 原地归并（O(k·g)，每组一次扫描，命中后累计次数）；
  没有重复的帧不做任何复制。
- 另提供 map 版 `DedupInPlace`（O(k) 期望，但每帧一次 map 分配）；实测在 k ≤ 64 时
  裸线性扫反而更快，因此 `DedupCommands` 默认走线性，map 版留给调用方在超大帧时选用。
- 键与比较按**实际生效的 int32 冲量**归一（`int32(c.PushX)`），
  与 `fixed.FromRaw` 的行为一致：`0` 与 `1<<32` 视为同一条（测试 `TestDedupNormalizesPushInt`）。

规模上界一句话：**把判定压到期望 O(k) 的代价是每帧一次 map 建表，实测在 k ≤ 64 时比
裸线性扫还贵；若 k 真到上千，应先按 body 分桶或改用位图，别让判定的常数超过执行本身。**

## 6. 一句话总结

> 两条相同指令的去重是否无损，取决于它们**是否在同一坐标（实体 × 速度分量）上累加同一非零量**；
> 完全相同的非零指令必然如此，所以「只留一条」就丢 `(m-1)d`，而「把次数折进冲量」在模 2³² 下恒精确。
> 「目标与字段交集为空」是不同指令可交换 / 可丢弃副本的充分条件；交集非空时丢量按组求和
> `Σ(m_g-1)d_g`，并可在不同组间对消。审计三组输入证明：归并恒与原序逐项相同，丢弃则按上式丢量。
