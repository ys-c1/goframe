# 定点乘法为什么不结合，以及为什么必须固定相乘顺序

本文针对 `internal/fixed` 的 Q16.16 表示：

```
Value 是有符号 32 位整数 v，真实值 = v / 2^16
```

记号：`a ⊗ b` 表示 `fixed.Mul` 的结果，
`p = a·b` 为 64 位精确积，`⌊·⌋` 为向下取整（`>> 16` 在 Go 里对负数是算术右移，
恰好等于 floor）。全文的“单位”均指 Q16.16 的原始单位 `1/2^16`。

## 0. 结论先行

1. 定点乘法**不满足结合律**。对任意三个定点数 `v,k,dt`，

   ```
   (v ⊗ k) ⊗ dt  −  v ⊗ (k ⊗ dt)  =  Δ,   |Δ| ≤ B
   B = ⌈ (|v| + |dt|) / 2^16 ⌉                                        (定理 1)
   ```

   界只依赖首尾因子 `v, dt`，与中间因子 `k` 无关；且存在取等例子（第 3 节 G2/G3）。

2. **固定顺序可以让差恒为零**：所有三因子乘积统一写成

   ```
   v ⊗ (k ⊗ dt)        // 右结合、系数对先行；生产入口 fixed.Mul3
   ```

   同一输入下，每次执行都走同一个表达式、同一次取整，结果逐位相同，
   因而 `Δ` 不再出现在任何两方之间。第 4 节说明为什么“必须”有一个约定，
   第 5 节给出约定本身与校验方式。

## 1. 两次取整，误差各归一处

设 `a·b = 2^16·p + s`，`0 ≤ s < 2^16`（欧几里得余数，`s` 是左乘这一步的取整余数），
`b·c = 2^16·q + t`，`0 ≤ t < 2^16`。则

```
a ⊗ b   = p                 (精确积 a·b 丢掉 s/2^16)
b ⊗ c   = q                 (精确积 b·c 丢掉 t/2^16)
```

两种结合顺序：

```
L = (a ⊗ b) ⊗ c = ⌊ (p·c) / 2^16 ⌋
R = a ⊗ (b ⊗ c) = ⌊ (a·q) / 2^16 ⌋
```

代入 `p = (ab − s)/2^16`、`q = (bc − t)/2^16`，并记 `X = abc / 2^32`：

```
L = ⌊ X − s·c / 2^32 ⌋
R = ⌊ X − a·t / 2^32 ⌋                                     (1)
```

两式相减并把外层 floor 的小数部分记为 `{·}`：

```
Δ = L − R = (a·t − s·c) / 2^32  +  ( {X − a·t/2^32} − {X − s·c/2^32} )   (2)
```

(2) 把差分成两块，含义正对“两次取整误差”：
`s` 是左结合中间积 `a·b` 的取整余数，`t` 是右结合中间积 `b·c` 的取整余数；
第一块 `(a·t − s·c)/2^32` 是这两笔余数被另一个因子放大后的净差，
第二块是两个外层 floor 的小数残差之差（落在 `(−1, 1)`）。
因此“两种顺序的差 = 两次取整误差之和”可落成精确等式 (2)，
其绝对值有界：`s·c/2^32 ∈ [0, |c|/2^16)`，`a·t/2^32 ∈ [0, |a|/2^16)`，于是

```
|Δ| ≤ |a·t − s·c|/2^32 + 1 < (|a| + |c|)/2^16 + 1
```

右端严格小于 `(|a|+|c|)/2^16 + 1`，因 `Δ` 是整数，取整后即

```
|Δ| ≤ ⌈ (|a| + |c|) / 2^16 ⌉ = B
```

且 `B` 与中间因子 `b` 无关。∎

上界紧：第 3 节 G2 的 `|Δ| = 6 = B`、G3 的 `|Δ| = 3 = B`。

> 注：实现里 `Mul` 的注释旧称“向零取整”，但 `>> 16` 对负数是 floor。
> 若真改成截断，余数可能为负，(1) 不再成立、界与归档数值都要重算。
> 现已把注释改成 floor 并加了 `TestMulRoundsFloor` 锁住语义。

## 2. 一个小例子（可手算）

`v = 0.1`、`k = 0.3`、`dt = 3.3`（原始值 6553、19660、216268）：

```
v ⊗ k = ⌊6553·19660 / 2^16⌋ = ⌊1965.82…⌋ = 1965
(v⊗k) ⊗ dt = ⌊1965·216268 / 2^16⌋ = ⌊6484.47…⌋ = 6484

k ⊗ dt = ⌊19660·216268 / 2^16⌋ = ⌊64877.76…⌋ = 64877
v ⊗ (k⊗dt) = ⌊6553·64877 / 2^16⌋ = ⌊6487.10…⌋ = 6487
```

左结合 6484、右结合 6487，差 3 个单位；界 `⌈(6553+216268)/2^16⌉ = ⌈3.40⌉ = 4`。

## 4. 为什么必须固定顺序

- **锁步即契约**：帧同步里两端的“同一物理量”必须在位级别相等。定点乘法虽然
  确定（同输入同平台必然同输出），但**只对确定的表达式**确定。`(v*k)*dt` 与
  `v*(k*dt)` 是两个不同函数，差最大 `B` 个单位。第 3 节 G1–G3 说明 `B` 通常
  是 3–6 个单位；在速度环里每帧都乘一次，误差会累积并放大。
- **实测轨迹会分叉**：`artifacts/mul-order/REPORT.md` 的 16 帧轨迹里，规范顺序
  与调换顺序在第 0 帧就出现首个差异（body 0 `posY` 差 31 个单位，来自 5 个子步
  的阻尼差累加），第 15 帧 `posX` 已差 1643 个单位。指纹从第 0 帧起就不同，
  回放对拍会在第一帧判定分叉。
- **编译器/重构不保证顺序**：一旦三因子写成 `v.Mul(k).Mul(dt)`，看起来像
  “同一条公式换个写法”，review 和后续维护很容易在“优化”时调换相邻乘法，
  或把系数外提/内联改变结合位置。约定必须写进代码注释与单一入口，让调换成为
  **可见的**改动，而不是顺手改。

## 5. 顺序约定（写进代码，避免被调回去）

约定：**三因子乘积一律 `v*(k*dt)`：右结合、系数对先行。**

- 单一入口：`fixed.Mul3(v, k, dt)`（循环外提时用 `Mul3Coef` 得到 `k*dt`，
  再用 `Mul3By`），生产代码不得直接写两次 `Mul` 链。
- 生产落点：`internal/sim.Integrate` 的阻尼冲量 `v*(k*dt)`；
  注释里标明了顺序与原因，并指向本文件。
- 语义护栏：`TestMulRoundsFloor` 锁住 `Mul` 的 floor 方向（定理 1 的前提），
  `TestMul3CoefAndByEquivalent` 锁住“系数外提”与逐个 `Mul3` 逐位等价。
- 实验台 `internal/orderlab` 的 Canonical 路径与 `api.World` 逐帧对拍，
  保证归档数字确实代表生产实现。

后续若要改顺序，必须同时重算：`fixed.Mul3Bound`、第 3 节三组数、
`artifacts/mul-order/` 全部归档、以及所有历史回放的指纹基线。这使调换成为
一次显式的、需要重新取证的变更。

## 6. 反例：故意调换一次

`internal/orderlab` 提供 `Swapped` 路径，只在三因子乘积处改写为 `(v⊗k)⊗dt`，
其余公式与 Canonical 完全相同。用第 5 节同一份输入（bodies=4、substeps=5、
gravity=3.0、drag=0.13）跑 16 帧，轨迹存档见 `artifacts/mul-order/TRACE.md`：

- 首次分叉：第 0 帧；
- 首个字段差异：body 0 `posY` = 1084884（规范） vs 1084853（调换），差 31；
- 第 15 帧：body 0 `posX` 差 1643 个单位，两轨指纹完全不同。

回归测试 `internal/orderlab/orderlab_test.go:TestSwappedDiverges` 断言调换后
有限帧内必然分叉；如果有人把反例路径也改回规范写法，该测试会失败。
用下面的命令可随时重建全部归档：

```
go run ./cmd/goorder -out artifacts/mul-order
go test ./internal/fixed/ ./internal/orderlab/
```
