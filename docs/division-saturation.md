# 定点除零返回零的不连续性，与带符号饱和除法

本文回答四件事：

1. 除零返回零为什么在除数过零时引入不连续，跳变量是多少；
2. 带符号饱和除法为什么能把跳变压到有界，界与饱和阈值是什么关系；
3. 饱和阈值为什么不能拍脑袋定，以及如何由速度的最大量级反推；
4. 接近除零的输入与常规输入，两种实现的跳变量差多少。

所有数值均由 `cmd/satdemo` 与 `internal/fixed` 的实际运行产生，可复算。

## 1. 符号与场景

`internal/fixed` 是 Q16.16 定点数，记真实值

$$
q = \frac{a}{b}, \qquad a, b \in \mathbb{R},
$$

`Div` 的实现是 `(int64(a)<<16)/int64(b)`，并在 `b == 0` 时直接返回零。

除法结果在本内核中会作为速度/速度修正项被逐帧累加到位置：`pos += q`。
因此 `q` 在某一帧的台阶会原样变成位置的台阶——这就是“速度突变时位置跳了一下”。
下文把 `b` 随帧扫过零作为复现场景，数据来自 `cmd/satdemo`。

## 2. 返回零在除数过零处引入不连续

### 2.1 不连续性的证明

旧行为是分段函数

$$
\operatorname{Div}_0(a,b)=
\begin{cases}
a/b, & b \neq 0,\\
0,   & b = 0.
\end{cases}
$$

固定 `a ≠ 0`，让 `b` 从正、负两侧趋近零：

$$
\lim_{b\to 0^+}\frac{a}{b}=+\infty\cdot\operatorname{sgn}(a),\qquad
\lim_{b\to 0^-}\frac{a}{b}=-\infty\cdot\operatorname{sgn}(a),
$$

而函数在 `b = 0` 的定义值是 `0`。两侧极限既不相等，也不等于函数值，
故 `Div₀(a, b)` 在 `b = 0` 处不连续。更糟的是它把**符号信息也丢了**：
无论被除数正负，除零一律给零。

### 2.2 跳变量等于被除数与除数之比

取过零前最后一个非零除数 `b = ε`（`ε ≠ 0`），下一帧 `b = 0`。两帧输出之差为

$$
\Delta
= \operatorname{Div}_0(a,0)-\operatorname{Div}_0(a,\varepsilon)
= 0 - \frac{a}{\varepsilon}
= -\frac{a}{\varepsilon}.
$$

即**过零帧的跳变量（绝对值）就是被除数与除数之比 `|a/ε|`**，且这个量随
`ε → 0` 无界。位置逐帧累加 `q`，所以位置在同一帧出现同样大小的台阶。

实测（`a = 4.0`，轨迹数据 `artifacts/trajectory.csv`，过零前一帧 `b = 0.5`）：

| 帧 | 除数 b | 旧 Div 输出 q | 累计位置 |
|---|---|---|---|
| 7 | +0.5 | +8.0000 | 21.7428 |
| 8 | **0** | **0.0000** | 21.7428（停滞） |
| 9 | −0.5 | −8.0000 | 13.7428（反向跳 8） |

过零帧的输出台阶 `|0 − 8| = 8 = |4 / 0.5|`，与公式一致；下一帧再反向跳 8。
除数越小，这个台阶越大，且没有上限。

### 2.3 定点实现还会截断回绕

Q16.16 用 int32 承载结果。真实商超过 int32 范围时，Go 的 int32 转换按
2³² 回绕，符号和量级会同时损坏，夹紧无从谈起。实测（`a = 2.0`）：

- `b` 原始值为 2（真实 `b ≈ 3.05×10⁻⁵`）：真实商 `≈ 65536`，截断后 **0**；
- `b` 原始值为 1（真实 `b ≈ 1.53×10⁻⁵`）：真实商 `≈ 131072 = 2¹⁷`，
  截断后同样 **0**。

也就是说，旧实现对“接近除零”的响应不是平滑变大，而是**无界增大后突然归零、
甚至可能翻到反号**，状态指纹会因此出现难以追查的跳变。

## 3. 带符号饱和除法把跳变压到有界

### 3.1 定义

给定正的饱和阈值 `S`，带符号饱和除法为

$$
\operatorname{SatDiv}(a,b;S)=\operatorname{clamp}\!\left(\frac{a}{b},\,-S,\,+S\right),
\quad b\neq 0,
$$

除零不取零，而是取被除数的符号顶到边界：

$$
\operatorname{SatDiv}(a,0;S)=
\begin{cases}
+S, & a>0,\\
-S, & a<0,\\
 0, & a=0.
\end{cases}
$$

### 3.2 有界性证明

对任意输入，输出恒落在闭区间 `[−S, +S]`。任意相邻两帧 `q₁, q₂` 的输出跳变满足

$$
|q_2-q_1|\ \le\ |q_2|+|q_1|\ \le\ 2S.
$$

**一行结论：`|Δq| ≤ 2S`——输出被夹在 `[−S, +S]`，任意帧间跳变的上界就是两倍饱和阈值。**

除数过零这个最坏点也在界内：`b → 0⁺` 与 `b → 0⁻` 分别饱和到
`+S·sgn(a)` 与 `−S·sgn(a)`，跨零台阶恰为 `2S`，且符号始终正确。
实测（`S = 20`，`cmd/satdemo` 标准输出）：

```
S=20.0  饱和除法过零两侧台阶 |+20.0 -> -20.0| = 40.0 <= 2S=40.0
```

因为位置每帧累加 `q`，位置的单帧台阶同样不超过 `2S`，轨迹不再出现无界跳变。

### 3.3 实现中的符号处理（`fixed.Value.SatDiv`）

符号必须在**收窄成 int32 之前**处理完，否则截断回绕已经把符号破坏，再夹紧会
夹到错误的一侧。实现约定（见 `internal/fixed/fixed.go`）：

1. 除数为零：不返回零，按被除数符号给 `+sat` / `−sat`；被除数也为零才给 0；
2. 被除数为零、除数非零：直接给 0，不进除法；
3. 普通情形：在 **int64 域**完成 `(a<<16)/b`，商的符号由被除数与除数异号
   自然得到（Go 整数除法向零取整）；
4. 在 int64 域与 `±sat` 比较并夹紧，最后才转回 int32——回绕在这一步之前
   就被排除；
5. `sat <= 0` 视为调用方配置错误，退化为返回零，防止错误阈值放大输出。

`internal/fixed/fixed_test.go` 覆盖了上述每条约定，包括“旧除法截断归零、
饱和除法仍能保留符号并夹紧”的对照用例。

## 4. 饱和阈值不能拍：由速度的最大量级反推

### 4.1 反推关系

设除法结果作为速度类量，设计包络为 `|v| ≤ Vmax`（任何合法输入都不应产生
超过 `Vmax` 的速度）。要让饱和层**只拦截越界输入、绝不误伤合法输入**，
阈值必须正好取在包络边界：

$$
\boxed{\,S = V_{\max}\,}
\qquad\text{（Q16.16 原始值：}\ \texttt{sat = FromInt(Vmax)}\,\texttt{）}.
$$

- 取 `S < Vmax`：合法输入 `a/b ∈ (S, Vmax]` 会被错误夹断，正常轨迹被改写；
- 取 `S > Vmax`：本该挡住的越界速度漏过，包络不变量被破坏。

`cmd/satdemo` 取 `Vmax = 20`，故 `S = FromInt(20)`。实际工程中 `Vmax`
应由 `api.Options` 的参数声明处给出（与 `Bodies/SubSteps/Gravity` 同级），
而不是散落在调用点。

### 4.2 超过该量级的输入本来就不该出现

`S = Vmax` 意味着：**触发饱和的唯一条件是 `|a/b| > Vmax`，即输入本身已经
超出设计包络**。这类输入按契约应在指令校验层（`Options.validate` /
`World.Step` 的命令检查）直接拒绝；饱和不是常规处理路径，而是数值层的
最后一道防线，保证即便脏输入漏进来，输出也不会无界、不会截断回绕。
因此阈值不是一个可调的“手感参数”，而是包络不变量在数值层的投影。

## 5. 近除零输入与常规输入的跳变量对照

固定被除数 `a = 2.0`、`S = 20`，数据由 `cmd/satdemo` 写入
`artifacts/jump-table.csv`。“帧间跳变”是相对上一采样点（`|b|` 更大、同号）
的输出差。

| 输入 b | 旧 Div 输出 | SatDiv 输出 | 旧帧间跳变 | SatDiv 帧间跳变 |
|---|---|---|---|---|
| 常规 +4.0 | 0.5 | 0.5 | — | — |
| 常规 +1.0 | 2.0 | 2.0 | 1.5 | 1.5 |
| 近零 +0.5 | 4.0 | 4.0 | 2.0 | 2.0 |
| 近零 +0.125 | 16.0 | 16.0 | 12.0 | 12.0 |
| 近零 +0.0625 | **32.0** | 20.0 | 16.0 | **4.0** |
| 近零 raw=2（≈3.05e-5） | **0（截断）** | 20.0 | −32.0 | 0.0 |
| 回绕 raw=1（≈1.53e-5） | **0（截断）** | 20.0 | 0.0 | 0.0 |
| 精确除零 0 | **0（归零）** | 20.0 | 0.0 | 0.0 |
| 近零 raw=−1 | **0（截断）** | −20.0 | 0.0 | **−40.0** |
| 近零 raw=−2 | **0（截断）** | −20.0 | 0.0 | 0.0 |
| 近零 −0.0625 | **−32.0** | −20.0 | −32.0 | 0.0 |
| 近零 −0.125 | −16.0 | −16.0 | 16.0 | 4.0 |
| 常规 −1.0 | −2.0 | −2.0 | 14.0 | 14.0 |

可量化的差异：

- **常规区间（`|b| ≥ 0.125`，商未超 `S`）两者逐位相同**，帧间跳变完全一致
  （如 1.5、2.0、12.0），饱和层对合法输入零影响，由
  `TestSatDivMatchesDivInNormalRange` 锁定。
- **接近除零时分流**：`b = 0.0625` 处真实商 32 已越界，旧实现输出 32、
  帧间跳变 16；SatDiv 夹到 20、帧间跳变只有 4，跳变量差 **4 倍**。
- **更小除数旧实现直接截断归零**（raw=1/2 两行输出 0），跳变没有数学上界；
  SatDiv 恒定停在 ±20，跨零的最大台阶被钉死在 `2S = 40`（raw=−1 行的 −40）。
- 旧实现跨零处输出 `+32 → 0 → −32`（本例 raw 更大时）或全程归零，符号
  依赖回绕；SatDiv 始终 `+20 → +20 → −20`，符号正确、量级有界。

## 7. 复算方式

```bash
go test ./...                                   # 固定包单测与既有确定性测试
go run ./cmd/satdemo --out artifacts            # 生成 trajectory.csv / jump-table.csv
SITE=$(python3 -c "import os, matplotlib; print(os.path.dirname(os.path.dirname(matplotlib.__file__)))")
PYTHONPATH="$SITE" python3 -P artifacts/plot_trajectory.py \
  artifacts/trajectory.csv artifacts/trajectory.png
```

注：Python 用 `-P` 运行，避免脚本目录/当前目录进入 `sys.path`（防止同名模块
投毒）；matplotlib 所在的用户 site 目录通过显式 `PYTHONPATH` 提供。
既有 `Div` 与积分内核的状态指纹保持不变，本次改动只新增 `SatDiv`，
不改变任何既有回放轨迹。
