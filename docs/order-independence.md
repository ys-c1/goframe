# 积分顺序与末态唯一性

## 0. 模型与记号

一次实体间交互（`sim.Shove`）是一个状态变换：

- 读集合 `R(k) = {Src}`：冲量 `j_k = gain_k · v(Src) + base_k` 在执行瞬间从共享状态读出
- 写集合 `W(k) = {Dst}`：把 `j_k` 加回共享状态 `v(Dst) += j_k`

设 `x_k` 为交互 `k` 执行时读到的状态，`f_k(x_k)` 是它计算出的冲量，状态转移为
`s → s + e_{Dst(k)} · f_k(x_k)`。`x_k` 不是入参，而是执行时刻从共享状态 `s` 中读出的值——
这是顺序问题的根源。

## 1. 命题一：顺序影响结果，当且仅当状态被共享写入；影响量就是冲量差

取两条交互 `a`、`b`，比较两种相邻顺序 `ab` 与 `ba`，初始状态同为 `s`。

**顺序 ab：**

1. `a` 读到 `x_a = s[R(a)]`，写入 `s' = s + e_{W(a)} f_a(x_a)`
2. `b` 读到 `x_b = s'[R(b)]`

**顺序 ba：**

1. `b` 读到 `x_b⁰ = s[R(b)]`，写入 `s'' = s + e_{W(b)} f_b(x_b⁰)`
2. `a` 读到 `x_a' = s''[R(a)]`

分两种情形。

### 情形 A：`W(a) ∩ R(b) = ∅` 且 `W(b) ∩ R(a) = ∅`

`a` 的写入不落在 `b` 的读集合内，反之亦然，于是 `x_b = x_b⁰`、`x_a = x_a'`，
两条交互算出的冲量在两种顺序下完全相同。状态更新只是加法，加法可交换：

```
s_ab = s + e_W(a) f_a(x_a) + e_W(b) f_b(x_b) = s_ba
```

末态相同，**冲量差为零**。

### 情形 B：共享写入，即 `W(a) ∩ R(b) ≠ ∅`（或反向）

`a` 先执行改变了 `b` 要读的状态。`b` 在两种顺序下读到的值之差为

```
Δx_b = x_b − x_b⁰ = f_a(x_a)          （W(a) 命中 R(b) 时）
```

因此 `b` 的冲量差为

```
Δj_b = f_b(x_b) − f_b(x_b⁰) = gain_b · Δx_b = gain_b · f_a(x_a)
```

末态之差完全由冲量差解释：

```
s_ab − s_ba = e_W(b) · Δj_b
```

即**影响量就是两实体交互的冲量差，没有别的来源**。定点数下没有浮点舍入项，
该恒等式逐字节成立（实验 `g2-mutual`、`g3-cycle` 的轨迹可逐项核对）。

**结论（命题一）**：积分顺序影响结果的充要原因是某条交互的写集合命中另一条交互的
读集合——共享写入被对方当输入读出；顺序造成的末态差异恒等于受影响交互的冲量差
`gain · Δx`。读集合只与写集合不相交的交互（包括纯常量冲量 `gain=0`）天然可交换。

## 2. 命题二：按实体编号固定顺序可让结果唯一

### 充分性

定义全序键 `key(k) = (Src, Dst, Gain, Base)`，对任意一帧的交互多重集按该键排序后再执行。

1. 键是**全序**：四个分量逐级决胜，任意两个不同交互都可比较，不存在未决并列；
2. 排序只依赖交互内容，不依赖调用方传入的先后；
3. 同一多重集的任意排列，规范化后得到**同一个序列**，确定性内核执行同一序列必得同一末态。

故同一组输入在任意调用顺序下末态（及哈希）唯一。`api.StepWith` 对指令与交互都做此规范化。

### 必要性（充要条件）

规范化能产生唯一末态，当且仅当排序键是交互集合上的**全序**，即：

> 任意两条内容不同的交互，键值必须不同；键值相同的并列项必须由附加分量决胜，
> 不能把相对顺序留给输入。

若键不是全序（存在不可决胜的并列项），稳定排序会保留输入的相对顺序，规范化退化为恒等映射，
命题一情形 B 的冲量差原样保留，唯一性失效。

### 反例：去掉决胜字段后条件失效

同一实体上的两条自作用（`R∩W={0}`，共享写入最强的情形）：

```
I0 = {Src:0, Dst:0, gain:1, base:0}   v ← v
I1 = {Src:0, Dst:0, gain:2, base:1}   v ← 2v + 1
初态 v0 = 1
```

- **全序键 `(Src,Dst,Gain,Base)`**：两种输入顺序都规范化为 I0→I1：
  `1 →(I0) 1 →(I1) 3`，末态 `v0=7`（Q16.16 原始值 458752），哈希 `1fbc4fc4f78be94f`。
- **残缺键 `(Src,Dst)`**：两条交互键值相同、无决胜，稳定排序保留输入顺序：
  - 输入 I0→I1：`1 → 1 → 3`，得 `v0=7`
  - 输入 I1→I0：`1 →(I1) 3 →(I0) 3`，得 `v0=8`（524288，哈希 `bcbc4fc2197be94f`）

两种调用顺序末态不同、哈希不同，唯一性失效。这正是全序条件被去掉后的必然结果
（代码见 `cmd/orderlab` 的 `writeTieBreakCounterexample`，测试见 `sim.TestTieBreakRequired`）。

第三栏是状态指纹证据。完整每顺序对照见 `artifacts/orderlab/summary.md`。

## 4. 固定顺序的代价

按实体编号固定顺序用确定性换了调度自由，代价包括：

- **无法利用缓存局部性**：交互的物理聚集（空间邻近的实体簇、同一内存页上的数据）
  与编号顺序未必一致，不能按数据驻留情况重排计算，cache miss 与预取效果只能被动接受；
- 无法做依赖感知的并行/乱序调度，即便两条交互写集合不相交、本可并发，也要排在串行序列里；
- 每帧排序有 `O(m log m)` 开销，且编号一旦承担语义，实体的增删与编号复用需要额外约束。

若要兼顾，可只对存在 `R∩W` 依赖的连通分量强制全序，分量之间仍允许自由调度——
分量边界恰好由命题一的可交换条件给出。
