# 状态指纹碰撞证明与修复

## 背景

`internal/fixed` 的 `Value` 是 Q16.16 定点数，底层为 **int32，32 位全部承载有效信息**
（高 16 位是整数部分，低 16 位是小数部分，符号位也在高位）。`sim.State.Raw()`
按固定顺序导出 `[]int32`，`hash.State` 用 FNV-1a（64 位）逐个字段混合：

```
h0 = offset
h_{i+1} = (h_i XOR m(v_i)) * prime   （mod 2^64）
```

故障类是**在混合前把每个字段截到低 k 位**：`m(v) = uint64(uintk(v))`。
现网 `uint64(uint32(v))` 对 int32 无损，但它示范了这种"先截位再混合"的写法；
一旦截断宽度小于字段原生宽度（如 uint16），高位就对指纹完全不可见。

## 一、为什么"低位相同、高位不同"必然同哈希

**记号。** 设字段原生宽度为 w（这里 w=32），截断宽度为 k<w。截断函数
`T_k(v) = v mod 2^k`，只保留低 k 位。两状态 A、B 的原始字段序列为
`(a_1..a_n)`、`(b_1..b_n)`，帧号同为 t。

**构造条件（同时满足即可保证碰撞）：**

1. 对每个字段 i，`T_k(a_i) = T_k(b_i)`，即低 k 位逐字段相等；
2. 至少存在一个字段 j 使 `a_j ≠ b_j`，差异完全落在被丢弃的高 w−k 位
   （即 `a_j XOR b_j` 的所有 1 都在第 k 位及以上）；
3. 帧号与字段顺序一致。

**证明。** FNV-1a 的第 i 步只依赖上一步状态与当前混合输入 `m(v_i)`。由条件 1，
对所有 i 都有 `m(a_i) = T_k(a_i) = T_k(b_i) = m(b_i)`；帧号输入同理相等。
于是两个序列喂给混合器的**每一步输入都相同**。由归纳法，初始值同为 offset、
每步 XOR 与乘法（mod 2^64）的输入相同，故每一步结果相同，最终
`H(A) = H(B)`。差异所在的高 w−k 位从未进入任何一次运算，对指纹不可见。∎

**碰撞规模。** 每个差异字段的高 w−k 位有 `2^(w−k)` 种取值，截断后全部塌缩到
同一个低 k 位值上，构成一个大小为 `2^(w−k)` 的碰撞等价类；多字段独立，连乘。
w=32、k=16 时单字段等价类大小为 `2^16 = 65536`，两个差异字段为 `2^32`。

## 二、把高位纳入混合后为什么不再冲突

修复后 `m(v) = uint64(int64(v))`。int32→int64 是符号扩展、int64→uint64 是
按位重解释，复合映射是 **int32 到 uint64 的单射**：不同的 int32 必映射到不同
uint64，32 位（含符号位）无一丢失。

设 A、B 是满足上面条件 2 的真实分叉状态，取差异字段 j，`a_j ≠ b_j`。由单射性
`m(a_j) ≠ m(b_j)`，即在第 j 步两个序列的混合输入首次出现差异。FNV-1a 的乘法
常量 `prime` 为奇数，在 mod 2^64 环上是可逆元，乘以它（以及前置 XOR）不会把
两个不同输入合并：因此该差异传播到后续每一步，最终 `H(A) ≠ H(B)`，对拍判为
**分叉**。测试中三组构造对在修复后的指纹上全部两两不同。

## 三、为什么只加宽位宽不够（具体构造）

加宽截断宽度（k: 16→32）只在"字段原生宽度 w 恰好等于 32"时暂时掩盖问题，
**没有消除"先丢位再混合"这个机制本身**。只要未来某字段原生宽度超过截断宽度，
同一构造条件原样复活。把场景换成 64 位原生值（如纳秒时间戳、64 位序列号、
加宽后的定点值），仍用 uint32 截断混合：

```
x = 0x00000000_00000001
y = 0x00000002_00000001
```

低 32 位都是 `0x00000001`，高 32 位分别为 `0x00000000` 与 `0x00000002`，`x≠y`。
uint32 截断后 `T_32(x)=T_32(y)=1`，由第一节的同一论证，二者必然同哈希——
这正是 `TestWideningAloneFails` 断言的反例。继续把宽度加到 64，只要再出现
128 位字段就再撞一次，属"追着数据宽度打补丁"。根治办法是**始终混合字段的
完整原生宽度、不做任何截断**（本修复即对 int32 全位混合），而不是挑选一个
更宽但仍有限的截断宽度。

## 四、验证结果

`go test ./...` 全绿。三组构造的对照（截断宽度 k=16，原生宽度 w=32）：

| 构造 | 冲突等价类大小 | 截断位宽 | 截位哈希判定 | 全位哈希判定 |
|---|---|---|---|---|
| c1-single-field（单字段高位不同） | 65536 = 2^16 | 16 | 一致（错误） | 分叉（不同指纹） |
| c2-multi-field（两字段高位不同） | 4294967296 = 2^32 | 16 | 一致（错误） | 分叉（不同指纹） |
| c3-realistic（带重力，posX 高位翻转） | 65536 = 2^16 | 16 | 一致（错误） | 分叉（不同指纹） |

每组状态对只改高位、低位严格一致，留档于 `internal/hash/testdata/*.json`
（`low16_bits_equal: true` 且 `raw_different: true`），便于人工对照。
`api/fork_test.go` 在对外入口复跑：同指令序列指纹一致（无误报），
仅高位不同的状态对指纹不同（无漏报，判分叉）。
