# 回滚深度分析：为什么"经验五帧"在抖动下必然越界

帧长 `T = 50ms`（20Hz），仿真 600 帧/档，实体数 8。
延迟分布为离散帧延迟，整数千分位质量，固定种子 LCG 采样，跨机器逐位可复现
（`go run ./cmd/goframe rollback` 两次运行产物 `diff -r` 为空）。

---

## 1. 证明一：所需回滚深度由延迟分布的上分位决定

### 1.1 符号与窗口不变量

设帧长为 `T`（毫秒），第 `t` 帧的远端输入在网络上的单向延迟为随机变量
`L_t`（毫秒）。该输入的到达时刻为

```
a_t = t·T + L_t
```

回滚引擎在每个时钟帧只保留最近 `D+1` 个**推进前**状态快照（环形缓冲，
容量 `D+1`）。时钟走到第 `a` 帧、尚未推进时，环内快照对应帧号
`[a−D−1, a−1]`，能回滚的最老生效帧是 `a−D−1`。因此输入 `(t, a_t)`
可被回滚的充要条件是

```
t ≥ a_t − D − 1
```

### 1.2 延迟上界推出深度下界

把 `a_t = t·T + L_t` 代入（帧号域中 `a = t + d_t`，`d_t = L_t/T`）：

```
t ≥ (t + d_t) − D − 1  ⇔  d_t ≤ D + 1
```

即：**一条输入能被正确处理，当且仅当它的帧延迟不超过 D+1。**
（推进前快照让边界帧 `d=D+1` 仍可回滚；若环改存推进后快照则收紧为
`d ≤ D`，差一帧。工程上按保守口径 `d ≤ D` 配深度即可，下文 D* 取
分位帧值，留了这一帧余量。）

要求引擎以概率不低于 `1−α` 覆盖任意一条输入（取 `α = 0.01`，即 p99），
保守设计需要

```
P(d_t ≤ D) ≥ 1 − α
```

满足该式的最小整数深度就是延迟分布的上分位数：

```
D* = min{ d ∈ ℕ : P(d_t ≤ d) ≥ 1−α }
   = Q_{1−α}(d_t)
```

换回毫秒单位，`Q_{1−α}(L)` 是延迟分布的 `(1−α)` 分位（毫秒）：

```
                Q_{1−α}(L)
   D* = ceil( ───────────── )
                    T
```

**结论：所需深度等于延迟分位与帧长之比（向上取整）。** 它与分布的均值
无关——均值再小，只要上分位超过 `D·T`，尾部输入就必然越界。"经验定五帧"
等于隐含假设 `Q_0.99(L) ≤ 5T = 250ms`，这个假设在 4G/弱网档不成立。

### 1.3 实验佐证（固定种子，600 帧经验分位，最近秩法 k=ceil(0.99n)）

| 档位 | 经验 p99（帧 / ms） | 理论 D* | D=D* 实测越界 |
|---|---|---|---|
| LAN | 2 / 100 | 2 | 0 |
| 4G | 7 / 350 | 7 | 0 |
| 弱网 | 13 / 650 | 13 | 0 |

三档均在 `D = p99 分位帧值` 时把 600 条输入全部纳入窗口，零越界，
与证明一致（测试 `TestDepthStarEliminatesOOB` 固化）。

## 2. 证明二：内存占用与深度成正比，及给定内存的最大深度

### 2.1 内存模型

每帧快照保存全部 `B` 个实体的 `(posX, posY, velX, velY)`，各为一个
Q16.16 定点数（4 字节）：

```
s = 4 字段 × 4 字节 × B = 16B 字节/帧
```

环必须同时持有当前帧与前 `D` 帧的推进前快照，共 `D+1` 份：

```
M(D) = (D + 1) · s = (D + 1) · 16B
```

`M` 对 `D` 是一阶线性关系，比例系数就是单帧快照 `s`。本仓库 `B=8` 时
`s = 128 字节`，故 `M(D) = 128(D+1)`。

### 2.2 给定内存预算的最大深度

预算 `M_budget` 下要求 `(D+1)·s ≤ M_budget`，解得

```
                ⎣ M_budget ⎦
   D_max = floor │──────────│ − 1
                ⎣    s     ⎦
```

`B=8`（s=128B）的数值表（测试 `TestMaxDepthFormula` 固化）：

| 预算 | D_max | 实际占用 |
|---|---|---|
| 512 B | 3 | 512 B |
| 1024 B | 7 | 1024 B |
| 2048 B | 15 | 2048 B |
| 4096 B | 31 | 4096 B |

注意环容量是 `D+1` 而非 `D`：1024 字节预算只能买 7 帧深度而非 8 帧，
差一帧就是一次不可回滚的越界。把第 1 节的 `D*` 代入可得预算可行性判据：

```
预算可行  ⇔  M_budget ≥ 16B · ( D* + 1 )
```

弱网档 `D*=13` 要求 `128×14 = 1792` 字节；若设备只给 1024 B
（D_max=7），预算内不可能覆盖 p99，这是硬约束，调参无法绕过。

## 3. 三档对比（三栏）

实测口径：每档 600 帧、每帧一条远端输入，`D=5` 对照与 `D=D*` 各跑一次，
数字直接取自 `artifacts/rollback/summary.md`。

| 指标 | LAN（seed …601） | 4G（seed …602） | 弱网 WAN（seed …603） |
|---|---|---|---|
| 延迟分布支撑（帧/ms） | 1–3 / 50–150 | 1–8 / 50–400 | 1–14 / 50–700 |
| 经验 p50 | 1 帧 / 50ms | 2 帧 / 100ms | 4 帧 / 200ms |
| 经验 p95 | 2 帧 / 100ms | 5 帧 / 250ms | 11 帧 / 550ms |
| **经验 p99（取分位值）** | **2 帧 / 100ms** | **7 帧 / 350ms** | **13 帧 / 650ms** |
| 最大延迟 | 3 帧 / 150ms | 8 帧 / 400ms | 14 帧 / 700ms |
| **所需深度 D*=ceil(p99/T)** | **2** | **7** | **13** |
| D=5 环内存（(D+1)×128B） | 768 B | 768 B | 768 B |
| D* 环内存 | 384 B（D=2） | 1024 B（D=7） | 1792 B（D=13） |
| **D=5 失败帧数（越界/600）** | **0（0.0%）** | **8（1.3%）** | **169（28.2%）** |
| D=5 成功回滚次数 | 599 | 590 | 428 |
| 首个越界 target / at 帧号 | 无 | tick 178 / at 186 | tick 3 / at 11 |
| D=D* 残余越界 | 0 | 0 | 0 |

读法：LAN 的 p99 只有 100ms，五帧深度是浪费（768B 里一半是空置冗余）；
4G 的 p99=350ms 已超出 250ms 的五帧覆盖半径，尾部 1.3% 输入越界；
弱网 p99=650ms，近三成输入落在窗口外，五帧深度等于没有回滚保护。

## 4. 深度不足时的失败模式：具体帧号越界行为

引擎的窗口不变量（`internal/rollback/engine.go`）：时钟处于帧 `a`、
深度 `D` 时，环内只存在 tick `[a−D−1, a−1]` 的推进前快照。
迟到输入 `(target=t, at=a)` 的处理分两种：

1. `t ≥ a−D−1`（即 `delay = a−t ≤ D+1`）：快照命中，恢复到 tick `t`
   推进前状态，重放 `t..a−1` 共 `a−t` 帧，记 `rollback` 事件；
2. `t < a−D−1`（即 `delay > D+1`）：目标快照已在窗口滑动时被环形覆盖
   驱逐，`Inject` 返回 `ErrOutOfWindow`，记 `oob` 事件，**输入被丢弃**。
   从窗口下界帧起，本地状态与"输入准时到达"的权威哈希永久偏离，
   之后无法自愈——后续任何回滚的起点本身就已经缺了这条输入。

### 4.1 4G 档 D=5 的首次失败（可复现，延迟取值见轨迹）

```
target=178, arrival=186, delay=8 帧 = 400ms, 当时窗口 [180,185]
```

- 第 178 帧的远端输入延迟 8 帧（`4g.trace.csv` 第 179 行：`178,8,186,400`）；
- 它在时钟帧 186 开始时到达。环存的是推进前快照：tick=186 时最近 6 份
  快照对应 tick 180..185，即窗口 `[180,185]`（下界 `a−D−1 = 186−5−1`）；
- `target=178 < windowLo=180`，目标快照在窗口滑过 tick 180 时已被环形覆盖驱逐；
- 行为：引擎拒绝回滚、丢弃该输入，tick 180 起状态哈希永久偏离权威序列。
- 4G 档 8 个失败帧全部带帧号记录在 `4g.failures.csv`：
  **178, 189, 331, 343, 376, 496, 536, 560**，对应延迟 7–8 帧
  （350–400ms），全部 > D=5。
- 等价判据：可回滚要求 `delay = a−target ≤ D+1 = 6`（推进前快照多保留
  一帧边界）；该输入 delay=8，超出两个帧位，必然越界。

### 4.2 弱网档 D=5 的首次失败

```
target=3, arrival=11, delay=8 帧 = 400ms, 当时窗口 [5,10]
```

- `wan.trace.csv` 第 4 行：`3,8,11,400`；
- 帧 11 时钟开始时窗口只回溯到 tick 5，`target=3 < 5`，越界两帧；
- 紧随其后 `target=0, arrival=12, delay=12 帧=600ms`，
  窗口 `[6,11]`，越界六帧——这正是 p99=650ms 分布的典型样本；
- 全档 169 个失败帧号逐条落盘 `wan.failures.csv`，前 20 个为
  `3, 0, 8, 13, 22, 20, 23, 25, 28, 30, 33, 34, 39, 40, 42, 53, 56, 62, 65, 61`。

### 4.3 边界行为（单元测试固化，`TestWindowBoundary`）

D=5、时钟 tick=8 时窗口为 `[2,7]`（下界 `8−5−1=2`）：

- `target=2, delay=6`（=D+1）：等于窗口最老帧，回滚成功，重放后哈希与权威一致；
- `target=1, delay=7`（>D+1）：低一帧即返回 `ErrOutOfWindow`。

成败只隔一帧，说明越界不是概率性的"偶尔不准"，而是 `delay > D+1` 时的
确定性帧号行为，这也是失败帧号可以被固定种子完整复现的原因。

## 5. 复现方式

```bash
go test ./...                                   # 全部不变量与复现性测试
go run ./cmd/goframe rollback --bodies 8 \
    --out artifacts/rollback                    # 三档实验，重跑产物逐字节相同
```

产物（每档一份，回滚日志完整保留）：

- `<tier>.trace.csv`：600 条 `(生效帧, 延迟帧, 到达帧, 延迟ms)`，失败帧的延迟取值在此核对；
- `<tier>.rollback.log`：全部 `advance / rollback / oob / diverge` 事件，含每帧窗口上下界与哈希；
- `<tier>.failures.csv`：越界失败的帧号、到达时刻、延迟、当时窗口与逐帧说明；
- `summary.md`：分位、深度、内存与失败计数汇总。
